# 탁카 정책서 (Policies)

> 3단계 산출물 중 **정책서만** 선택 진행. 기능명세·화면설계는 소급 가치 낮아 제외(2026-07-04 결정).
> 작성 방식: **기존 구현 코드에서 정책을 역추출**한 뒤, 론칭에 필요한 엣지케이스를 보강. 각 정책은 `상황 → 규칙 → 근거` 형식이며, 실제 구현 위치를 근거 컬럼에 명시한다.
> 🔴 표시는 **코드에 아직 미구현이거나 불명확 → 론칭 전 조치 필요**한 정책(=액션 아이템).

## 역할 정의 (Role Matrix)

| 역할 | 정의 | 주요 권한 |
|---|---|---|
| 화주(Shipper) | 탁송 의뢰인 | 의뢰 등록/취소, 입찰 수신·기사 선택, 에스크로 결제, 완료 확인, 리뷰, 분쟁 제기 |
| 기사(Driver) | 카 캐리어 운송인 | KYC 인증, 피드 입찰/즉시수락, 차량 상태 리포트, 완료 요청, 정산·출금 |
| 어드민(Admin) | 운영자 | KYC 심사, 분쟁 처리(정산 판정), 출금 승인, 사용자 관리 |

## 1. 계정과 인증

### POL-001 회원가입 조건
- **상황**: 신규 가입 시.
- **규칙**: 이메일 인증(Supabase Auth) 필수. 가입 시 역할(화주/기사) 선택. 1이메일 1계정. 만 14세 미만 가입 불가(🔴 현재 명시적 연령 확인 절차 없음 — 약관 고지+가입 체크 필요).
- **근거**: Supabase Auth 이메일 인증, `middleware.ts` 역할 기반 라우팅.

### POL-002 휴대폰 번호 인증(OTP)
- **상황**: 거래 신뢰가 필요한 행위(예: 의뢰/입찰) 전 본인 확인.
- **규칙**: 휴대폰 OTP 인증. OTP는 단기 유효(🔴 만료 시간·재발송 제한·시도 횟수 제한 값 정책 확정 필요).
- **근거**: `supabase/migrations/005_phone_otp.sql` (`phone_verifications`).

### POL-003 회원 탈퇴
- **상황**: 이용자가 탈퇴를 요청.
- **규칙**: 🔴 미구현. 진행 중 거래(에스크로 held/disputed)가 있으면 **탈퇴 보류**. 탈퇴 시 개인정보는 지체 없이 파기하되, 전자상거래법·세법상 보존 의무 항목(결제·정산 기록)은 법정 기간 보존. 작성 콘텐츠(리뷰)는 익명화 처리. 재가입 제한 정책 확정 필요.
- **근거**: 정책 신설(현재 탈퇴 플로우 없음).

### POL-004 휴면 계정
- **상황**: 장기 미접속.
- **규칙**: 🔴 정책 미정. 1년 미접속 시 휴면 전환·사전 통지 기준 확정 필요(개인정보보호법 정합).

## 2. 권한과 접근

### POL-010 역할 기반 접근 통제
- **상황**: 다른 역할 전용 페이지·API 접근 시도.
- **규칙**: 미들웨어에서 역할 검사 후 **본인 역할 홈으로 리다이렉트**(숨김이 아닌 안내형 차단). 어드민 전용 경로는 어드민 외 접근 거부.
- **근거**: `middleware.ts`.

### POL-011 데이터 소유권 접근
- **상황**: 타인의 의뢰·결제·KYC 서류 조회 시도.
- **규칙**: 행 수준 보안(RLS, Row Level Security)으로 본인 소유 데이터만 접근. KYC 서류·차량 사진은 **private 스토리지**, 어드민 조회 시에도 서버 사이드 signed URL로만 노출.
- **근거**: `supabase/migrations/003_profile.sql` (storage RLS: `auth.uid() = foldername[1]`), KYC private storage + signed URL.

## 3. 데이터 생명주기

### POL-020 의뢰(Order) 수정·취소
- **상황**: 화주가 등록한 의뢰를 변경/취소.
- **규칙**: **매칭 성립 전**에는 자유 수정·취소 가능. 매칭·결제 후에는 취소가 아닌 **분쟁/취소 정책(POL-04x)** 경로로만 처리.
- **근거**: `app/actions/orders.ts`, 에스크로 상태 전이.

### POL-021 삭제 방식
- **상황**: 거래/사용자 데이터 삭제.
- **규칙**: 결제·정산·분쟁 이력은 **hard delete 금지**(감사·법정 보존). 상태 필드로 관리(soft). 연쇄 삭제는 금전 이력을 남기고 참조만 정리.
- **근거**: escrow/payments 상태 CHECK 컬럼(`held/released/refunded/disputed`, `paid/refunded`).

### POL-022 파일 업로드 제한 🔴
- **상황**: KYC 서류·차량 사진 업로드.
- **규칙**: 허용 확장자(이미지/PDF)·최대 용량·건당 매수 상한 확정 필요. 서버측 MIME 검증 권장.

## 4. 동시성과 중복

### POL-030 즉시수락 동시 경쟁 (핵심)
- **상황**: 여러 기사가 같은 의뢰를 동시에 즉시수락.
- **규칙**: 원자적 RPC로 처리. 의뢰 행을 `FOR UPDATE`로 잠근 뒤 상태 확인 → 이미 매칭된 경우 **`already_matched` 반환**(후착 기사 거절). 선착순 1명만 성립.
- **근거**: `supabase/migrations/20260627000001_atomic_rpcs.sql` `accept_order_atomic()`.

### POL-031 결제 중복 제출·재전송
- **상황**: 결제 승인 리다이렉트/새로고침으로 confirm 중복 호출.
- **규칙**: 결제 confirm은 **멱등(idempotent)** 처리. GET success 리다이렉트 + POST confirm 이중 경로 모두 동일 결제키에 대해 1회만 에스크로 held 생성.
- **근거**: `app/api/payments/toss/success/route.ts`, `.../confirm/route.ts`.

### POL-032 출금 동시 요청
- **상황**: 잔액에 대한 동시 출금 요청.
- **규칙**: 지갑 행 `FOR UPDATE` 잠금으로 잔액 초과 출금 방지.
- **근거**: `request_withdrawal_atomic()`.

## 5. 금전 (에스크로·수수료·정산)

### POL-040 에스크로 상태 전이
- **상황**: 결제~정산 전 과정.
- **규칙**: 에스크로 상태는 `held`(결제 보관) → `released`(기사 정산) / `refunded`(화주 환불) / `disputed`(동결). 분쟁 제기 시 `disputed`로 전환되어 **72h 자동 해제 크론을 차단**.
- **근거**: `001_initial_schema.sql` escrow status CHECK, `app/actions/disputes.ts`.

### POL-041 72시간 자동 정산
- **상황**: 기사가 완료 요청 후 화주가 확인하지 않음.
- **규칙**: 기사 완료 요청 시각(`completion_requested_at`) 기준 **72시간 경과 시 자동 released**. 매일 자정 크론 실행, `disputed` 건은 제외.
- **근거**: `app/api/admin/escrow/auto-release/route.ts` (cutoff = now-72h), `vercel.json` cron `0 0 * * *`, `007_completion_requested.sql`.

### POL-042 플랫폼 수수료
- **상황**: 탁송 완료 정산.
- **규칙**: **완료 건에 한해 기사 정산액의 4%** 공제(기사 96% 수령). 화주는 수수료 무부담. **취소·환불 건에는 수수료 미부과.** 수수료율 변경 시 **최소 30일 전 공지**.
- **근거**: `app/terms/page.tsx` 제7조, `escrow.platform_fee`.

### POL-043 취소·환불
- **상황**: 거래 취소.
- **규칙**:
  - 탁송 시작 **전** 취소 → 전액 환불.
  - **기사 귀책**(배정 후 미이행 등) → 화주 전액 환불.
  - **화주 귀책** 취소 → 취소 시점에 따라 위약금 발생 가능(🔴 단계별 위약금율 표 확정 필요).
  - 환불은 원결제 수단으로 **영업일 5~10일** 이내 처리.
- **근거**: `app/terms/page.tsx` 제6조 ④⑤⑥⑦.

### POL-044 분쟁 정산 판정
- **상황**: 화주-기사 분쟁을 어드민이 판정.
- **규칙**: 세 가지 결과 — `driver_win`(기사에게 released) / `shipper_win`(화주에게 refunded) / `partial_refund`(기사 정산액의 **50%** 지급, 잔여 환불).
- **근거**: `app/actions/admin.ts` (partial: driver 50% payout), `disputes.resolution` CHECK.

### POL-045 긴급 부스팅 결제
- **상황**: 의뢰 상단 노출을 위한 별도 결제.
- **규칙**: 부스팅은 에스크로와 **별개 결제**이며 노출 서비스 대가로 **원칙적 환불 불가**(🔴 노출 미제공 등 예외 환불 조건 명문화 필요).
- **근거**: 긴급 부스팅(Urgent) 결제 로직.

## 6. KYC 인증 정책

### POL-050 KYC 자동 판정 임계값
- **상황**: 기사/화주 KYC 서류 제출.
- **규칙**: Claude Vision 신뢰도(confidence) 기준 — **≥ 0.72 자동 승인, < 0.35 자동 거절, 그 사이 수동 검토(`manual_review`)**. 사업자등록증 미제출 화주는 자동 승인.
- **근거**: `app/api/kyc/verify/route.ts` L464~470, L358.

### POL-051 KYC 미인증 기사 제한
- **상황**: 인증 미완료·거절·수동검토 대기 기사의 거래 시도.
- **규칙**: KYC 승인 전 기사는 입찰/즉시수락 **불가**. 수동검토 대기 상태는 이용자에게 "접수됨, 검토 후 안내" 고지.
- **근거**: `kyc/verify/route.ts` L474, L525.

### POL-052 KYC 재제출
- **상황**: 거절된 기사의 재도전.
- **규칙**: 🔴 재제출 허용 여부·횟수 제한·쿨다운 정책 확정 필요(반복 위·변조 제출 방지).

- **규칙**: 위치정보법상 **개인위치정보 수집·이용에 별도 동의** 필요. 추적은 **진행 중 거래에 한정**, 완료 후 수집 중단, 위치 이력 보관기간·파기 기준 명시.
- **근거**: `driver_locations`(006) — 🔴 현재 별도 동의 UI/보관정책 미확인, 론칭 전 필수.

### POL-082 KYC 서류 접근 통제

- **규칙**: private 스토리지 저장, 소유자 본인 또는 심사 어드민만 서버 발급 signed URL로 접근. 로그로 접근 감사.
