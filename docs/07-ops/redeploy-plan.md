# 탁카 재배포 / 롤백 계획 (Stage 7)

대상: Vercel(Next.js 15) + Supabase(PostgreSQL). 배포 URL hwamulro.vercel.app / takca.vercel.app. 크론 `vercel.json` `0 0 * * *`(에스크로 자동해제).

이번 개선(개선계획 이번 스프린트 항목)을 안전 배포하는 절차. **DB 우선, 코드 후행** 원칙(하위호환 전제). 비호환 변경은 expand–migrate–contract로 분리.

## 1. 배포 전 체크리스트
- [ ] `npx tsc --noEmit` exit 0 (현재 통과 확인됨)
- [ ] `next build` 로컬 성공 (DashboardCharts 빌드에러 수정 반영됨)
- [ ] 회귀 TC 재실행: TC-001, TC-007/008/009(인가), TC-020/021(결제·정산), TC-040/043(KYC)
- [ ] 신규 마이그레이션 **하위호환** 확인: 기존 코드가 새 컬럼/제약에도 동작하는가
- [ ] 위치정보 동의 배포 시 — 기존 사용자 재동의 유도 경로 준비
- [ ] 환경변수 확인: `TOSS_SECRET_KEY`, `CRON_SECRET`, `ANTHROPIC_API_KEY`, Supabase 키
- [ ] 롤백 포인트(직전 정상 배포 deployment id) 기록

## 2. 배포 순서
1. **Supabase 마이그레이션 먼저** (하위호환만): 예 — KYC 재시도 카운트 컬럼, 위치정보 동의 테이블, escrow 대사용 인덱스. 새 컬럼은 nullable/default로 추가(기존 코드 무영향).
2. **코드 배포** (Vercel): 개선 항목 반영본. 프리뷰 배포 → smoke test → 프로덕션 프로모션.
3. **크론/알림 설정**: 대사 크론·비용 알림·에러 트래킹 활성.
4. 비호환 변경(예: 컬럼 제거/제약 강화)은 이번에 배포하지 않고 expand–migrate–contract 후속 분리.

## 3. 배포 후 스모크 테스트 (프로덕션)

- [ ] 의뢰 등록(화주만) / 입찰(인증 기사만) 정상, 타역할 차단(BUG-001/002)
- [ ] 테스트 결제 1건: 정상 confirm → escrow held / 금액 불일치 요청 → 400(BUG-004)

- [ ] 에러 트래킹에 이벤트 유입 확인

## 4. 롤백 계획

### 수치 트리거 (하나라도 충족 시 즉시 롤백)
- 결제 confirm 5xx 비율 **> 2%** (5분 이동)
- KYC verify 오류율 **> 10%** 또는 Anthropic 비용 **> 평시 3배/시간**
- 로그인/대시보드 진입 실패(정상 사용자 리다이렉트 루프) **> 1%**
- escrow 대사 누락 **> 0건** 신규 발생
- 5xx 전체 **> 평시 5배** 또는 p95 응답 **> 3s** 지속 10분

### 롤백 절차
1. **코드**: Vercel 직전 정상 deployment로 **Instant Rollback**(프로모션 되돌리기). 수 초 내 복구.
2. **DB**: 이번 마이그레이션이 **추가형(하위호환)** 이면 코드만 롤백해도 안전(새 컬럼 미사용 상태로 복귀). 되돌릴 필요 없음.
3. **비가역 마이그레이션인 경우**(이번 배포에선 지양): 사전 준비한 down 마이그레이션 적용. down이 불가능하면(데이터 손실) → **롤백 대신 롤포워드**(hotfix)로 대응, 사전에 스냅샷/백업 확보 필수.
4. 크론/알림은 문제 원인이면 개별 비활성.

### 롤백 후
- 인시던트 기록(OPS 템플릿), RCA, 재발방지 반영 후 재시도.

## 5. 원칙 요약
- 추가형 마이그레이션만 이번 배포 → 코드 롤백만으로 안전한 되돌림 보장.
- 자금·개인정보 관련 변경은 프리뷰 + 스모크 + 대사 이중 확인 후 프로모션.
