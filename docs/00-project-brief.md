# 탁카 Project Brief

## 한 줄 정의
**차량 탁송이 필요한 화주**에게 **역제안 입찰(reverse-bidding) + 에스크로 안전거래**로 검증된 기사를 매칭해주는 차량 탁송 중개 플랫폼.

## 배경과 문제의식
차량 탁송(카 캐리어 등) 시장은 화주가 일일이 기사를 수소문해 전화로 흥정하는 비효율 구조다. 가격은 불투명하고, 선입금 후 잠적·차량 파손 분쟁 등 거래 신뢰 문제가 상존한다. 탁카는 흐름을 뒤집어 **화주가 의뢰를 올리면 기사들이 입찰하거나 즉시 수락**하게 하고, 결제금을 플랫폼이 보관했다 완료 시 정산하는 **에스크로**로 신뢰 문제를 해소한다. 이미 풀스택 MVP가 구현·배포된 상태이며, 이 파이프라인의 목적은 **실서비스 론칭 준비**다.

## 목표
- 비즈니스 목표: 실사용자·실결제가 오가는 서비스로 안전하게 론칭. 초기 거래에서 결제/정산/분쟁 사고 0건.
- 사용자 목표: 화주는 신뢰할 기사를 빠르고 투명하게, 기사는 헛걸음 없는 콜을 안정적으로.
- 학습/포트폴리오 목표: (해당 없음 — work 프로젝트)

## 범위 밖 (Out of Scope)
- 신규 기능 개발 (MVP 기능은 구현 완료로 간주)
- 1~4단계 사전 기획 문서의 소급 작성 (코드가 이미 존재 — 론칭 가치 낮음)
- 8단계 포트폴리오 (work 프로젝트, 대외 홍보용 아님)

## 제약 조건
- 기간: 2026.06 개발 시작, 현재 론칭 준비 단계
- 팀: 1인 (박효균) 풀스택
- 기술: Next.js 15 (App Router, Server Actions) + Supabase (PostgreSQL + RLS + Realtime + Storage). Toss Payments 에스크로, Anthropic Claude Vision KYC, Vercel 배포/Cron
- 도메인 규제: **결제·자금 보관(에스크로)** + **KYC 개인정보/신분증 처리** → 정책·운영 리스크 비중 높음. 화물자동차 운수사업 관련 중개 성격 검토 필요.

## 성공 기준
- 핵심 플로우 3종(역제안 입찰·에스크로 결제/정산·KYC 인증) QA 통과: 정상/오류/경계 시나리오 모두 검증.
- 운영 장애 시나리오 3종에 대해 탐지→대응→재발방지 플레이북 확보, 롤백 조건 명문화.
- 결제/정산/개인정보 관련 정책 엣지케이스(환불·분쟁·데이터 생명주기)가 문서로 확정.
