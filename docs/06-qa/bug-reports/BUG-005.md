# BUG-005 정산액을 escrow.driver_payout 대신 orders.price로 재계산

| 항목 | 값 |
|---|---|
| 심각도 | Major |
| 우선순위 | P3 |
| 상태 | Fixed |
| 관련 TC | TC-026 |
| 관련 POL | POL-040, POL-042 |
| 발견 위치 | `app/actions/orders.ts:150-151`(confirmCompletion), `app/api/admin/escrow/auto-release/route.ts:45-46` |

## 환경
- master, code-inspection.

## 기대 결과
- 정산액은 결제 시 escrow에 이미 저장된 `driver_payout`(실제 보관·정산 근거)을 사용해야 함. 실제 보관액이 정산의 단일 진실원본(source of truth).

## 실제 결과
- 두 정산 경로 모두 `orders.price`를 다시 `calculateFee`에 넣어 재계산. escrow에 저장된 `total_amount`/`driver_payout`을 사용하지 않음.

## 원인 분석 (확정)
- escrow.driver_payout 컬럼이 존재함에도 미사용. `orders.price`는 approveBid에서 낙찰가로 갱신되는 등 escrow 생성 시점 이후 변할 수 있어, 실제 보관액과 정산액이 어긋날 수 있음(과대/과소 정산).

## 조치 (제안)
- 정산 금액을 `escrow.driver_payout`에서 직접 사용:
```ts
// confirmCompletion / auto-release
const driverPayout = escrow.driver_payout
```
- escrow 조회 select에 `driver_payout` 포함. 재검증: TC-021·TC-022 회귀.

## 조치 결과 (Fixed)
- `orders.ts` confirmCompletion·`auto-release/route.ts` 모두 `escrow.driver_payout` 사용으로 변경, `calculateFee`/`orders(price)` 제거. tsc 통과.
