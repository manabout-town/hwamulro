# BUG-002 createOrder에 역할(role) 검사 없음 — 기사가 의뢰 등록 가능

| 항목 | 값 |
|---|---|
| 심각도 | Major |
| 우선순위 | P2 |
| 상태 | Fixed |
| 관련 TC | TC-008 |
| 관련 POL | POL-010(역할 접근) |
| 발견 위치 | `app/actions/orders.ts:8-41` (createOrder) |

## 환경
- master 브랜치 현재 코드, code-inspection.

## 재현 절차
1. 역할이 `driver`인 계정으로 로그인.
2. `createOrder` 서버액션을 origin/destination/price 등과 함께 직접 호출.

## 기대 결과
- POL-010상 **의뢰 등록은 화주(shipper) 전용**. 기사 호출은 차단돼야 함.

## 실제 결과
- `createOrder`는 로그인 여부만 확인하고 역할 미검사 → 기사 계정도 자신을 shipper_id로 하는 의뢰를 생성 가능. 이후 데이터 정합(기사↔화주 혼재) 깨짐.

## 원인 분석 (확정)
- 역할 가드 누락. 미들웨어 역할-영역 미강제(BUG-003)와 결합해 서버측 유일 방어선이 비어 있음.

## 조치 (제안)
```ts
const { data: profile } = await supabase.from("users").select("role").eq("id", user.id).single()
if (profile?.role !== "shipper") return { error: "화주만 의뢰를 등록할 수 있습니다" }
```
- 재검증: TC-008 재실행 + TC-001 통합여정(TC-060) 회귀.

## 조치 결과 (Fixed)
- `app/actions/orders.ts` createOrder에 role 가드 적용. `npx tsc --noEmit` 통과(해당 파일 에러 0). 기사 호출 차단, 화주 정상 등록 유지.
