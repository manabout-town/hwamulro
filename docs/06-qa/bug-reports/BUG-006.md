# BUG-006 결제 confirm 호출자가 해당 의뢰의 화주인지 미검증

| 항목 | 값 |
|---|---|
| 심각도 | Minor |
| 우선순위 | P3 |
| 상태 | Fixed (escrow 경로) / urgent 경로 잔여 |
| 관련 TC | TC-027 |
| 관련 POL | POL-011(데이터 소유권) |
| 발견 위치 | `app/api/payments/toss/confirm/route.ts:11-12,103-105` |

## 기대 결과
- POL-011: 결제 확정은 해당 order의 화주 본인만. 서버가 `order.shipper_id === user.id`를 확인해야 함.

## 실제 결과
- 로그인 여부만 확인. escrow 경로는 소유 검증 없음. urgent 경로는 `shipper_id: user.id`로 삽입만 하고 order 소유 확인 없음.

## 원인 분석 (확정)
- 소유권 가드 누락. 실제 악용은 유효 paymentKey/orderId 확보가 전제라 난이도는 있으나, 인가 원칙상 결함.

## 조치 (제안)
- escrow/urgent 모두 order 조회 후 `if (order.shipper_id !== user.id) return 403`.
- 재검증: TC-027 재실행 + TC-020 회귀.

## 조치 결과 (Fixed — escrow 경로)
- escrow 분기에 `order.shipper_id !== user.id` 403 가드 추가(BUG-004 수정과 동일 위치). tsc 통과.
- **잔여**: urgent 분기는 order 미조회 구조라 미적용. 부스팅 결제 소유검증은 후속(order 조회 추가 필요).
