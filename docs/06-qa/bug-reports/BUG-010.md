# BUG-010 approveBid 중복 매칭 시 raw DB 오류 노출

| 항목 | 값 |
|---|---|
| 심각도 | Minor |
| 우선순위 | P4 |
| 상태 | Open |
| 관련 TC | TC-011 |
| 관련 POL | POL-030(동시성) |
| 발견 위치 | `app/actions/bids.ts:59-65` |

## 기대 결과
- 이미 매칭된 의뢰에 승인 시도 시 사용자에게 "이미 매칭된 의뢰입니다" 등 친화적 메시지.

## 실제 결과
- 데이터 무결성은 `matches_unique_active_per_order` 부분 유니크 인덱스로 보호됨(중복 매칭 생성 안 됨 ✅). 그러나 insert 충돌 시 `matchError.message`(Postgres 유니크 위반 원문)를 그대로 반환 → UX 저하, 내부 제약명 노출.

## 원인 분석 (확정)
- approveBid이 acceptOrder와 달리 원자적 RPC를 쓰지 않고 raw insert 후 에러 원문 전달. 사전 status 재확인도 TOCTOU 존재하나 인덱스가 최종 방어.

## 조치 (제안)
- matchError code가 유니크 위반(23505)이면 "이미 다른 기사와 매칭된 의뢰입니다"로 변환 반환. 또는 approveBid도 원자적 RPC로 통일.
