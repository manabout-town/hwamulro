# BUG-003 미들웨어에 역할별 영역(shipper/driver) 접근 통제 없음

| 항목 | 값 |
|---|---|
| 심각도 | Major |
| 우선순위 | P2 |
| 상태 | Fixed |
| 관련 TC | TC-009, TC-006(연관) |
| 관련 POL | POL-010(권한과 접근) |
| 발견 위치 | `middleware.ts:54-78` |

## 환경
- master 브랜치 현재 코드, code-inspection.

## 재현 절차
1. verified 화주 계정으로 로그인.
2. 브라우저로 `/driver/feed`, `/driver/dashboard` 등 기사 전용 경로 접근.

## 기대 결과
- POL-010: 역할별 전용 영역은 타 역할 접근 시 차단(리다이렉트)돼야 함.

## 실제 결과
- 미들웨어는 (a) 미인증 KYC 게이트, (b) 로그인 사용자를 `/`·`/login`·`/signup`에서 역할 홈으로 보내는 처리만 함. **role ↔ path 영역 매핑 강제가 없음.** verified 화주는 KYC 게이트를 통과하므로 기사 전용 경로에 그대로 진입 가능. (반대로 기사도 화주 영역 접근 가능.)
- 서버액션 레벨 가드가 있는 곳(acceptOrder)은 방어되나, 없는 곳(BUG-001 submitBid, BUG-002 createOrder)은 무방비.

## 원인 분석 (확정)
- 인가를 미들웨어 KYC 게이트에만 의존. 역할-영역 규칙 부재.

## 조치 (제안)
- 미들웨어에 역할-접두어 매핑 추가(예: driver는 `/shipper/*` 접근 시 `/driver/dashboard`로, 그 반대도). API·공용 경로 예외 유지.
```ts
if (role === "shipper" && path.startsWith("/driver")) return NextResponse.redirect(new URL("/shipper/dashboard", request.url))
if (role === "driver" && path.startsWith("/shipper")) return NextResponse.redirect(new URL("/driver/dashboard", request.url))
```
- **주의(배포 앱)**: 경로 접두어 전수 확인 후 적용. 공용/공유 경로(chat, review, profile 등) 오차단 없는지 회귀 필요 → 적용 전 사용자 승인 권장.
- 재검증: TC-009 재실행 + 정상 화주/기사 각 영역 접근 회귀.

## 조치 결과 (Fixed)
- `middleware.ts`에 역할-영역 통제 추가. **비공개 하위경로 집합만 차단**(driver: dashboard/feed/mypage/wallet/orders/matches/schedule/calendar, shipper: dashboard/mypage/wallet/orders/calendar/drivers). `/driver/[userId]`(기사 프로필, 화주 조회용)·공유경로(chat/review/payment/orders/board)는 허용해 오차단 방지. tsc 통과.
