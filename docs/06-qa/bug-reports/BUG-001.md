# BUG-001 submitBid에 역할(role) 검사 없음 — 화주가 입찰 가능

| 항목 | 값 |
|---|---|
| 심각도 | Major |
| 우선순위 | P2 |
| 상태 | Fixed |
| 관련 TC | TC-007 |
| 관련 POL | POL-010(역할 접근), POL-051(기사 자격) |
| 발견 위치 | `app/actions/bids.ts:7-41` (submitBid) |

## 환경
- master 브랜치 현재 코드, code-inspection.

## 재현 절차
1. 역할이 `shipper`(또는 admin)인 계정으로 로그인(verified 상태).
2. 임의의 pending 의뢰 id를 확보.
3. `submitBid` 서버액션을 orderId/price/message와 함께 직접 호출(폼 재사용·수동 POST).

## 기대 결과
- POL-010 역할 매트릭스상 **입찰은 기사(driver) 전용**. 화주/관리자 호출은 "권한 없음"으로 차단돼야 함.

## 실제 결과
- `submitBid`는 로그인 여부만 확인하고 **역할을 검사하지 않음**. 본인 의뢰 여부(shipper_id === user.id)만 막으므로, 타인 의뢰에는 화주도 입찰 레코드를 생성할 수 있음.

## 원인 분석 (확정)
- `acceptOrder`(orders.ts:49)에는 `role !== "driver"` 가드가 있으나 `submitBid`에는 동일 가드가 누락됨. 미들웨어도 역할별 영역을 강제하지 않아(BUG-003) 서버측에서 걸러지지 않음.

## 조치 (제안)
- submitBid 시작부에 역할 가드 추가:
```ts
const { data: profile } = await supabase.from("users").select("role, verification_status").eq("id", user.id).single()
if (profile?.role !== "driver") return { error: "기사만 입찰할 수 있습니다" }
if (profile.verification_status !== "verified") return { error: "KYC 인증 후 입찰할 수 있습니다" } // POL-051 방어심화
```
- 재검증: TC-007 재실행 + TC-001(정상 기사 입찰) 회귀.

## 조치 결과 (Fixed)
- `app/actions/bids.ts` submitBid에 role+verification 가드 적용(위 제안대로). `npx tsc --noEmit` 통과(해당 파일 에러 0). 코드검사상 화주/미인증 호출 차단, 정상 기사 경로 유지. 라이브 재검증은 후속 회차.
